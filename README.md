# 英雄知识大乱斗 —— 扫码即参与版

学生**扫描二维码即可直接参与**，**无需老师创建房间号**；学生上传头像、输入昵称后，系统**自动均衡分配队伍**，随后进入回合制答题对战（答对释放技能选目标攻击、答错全队扣血、血量归零淘汰、最终排名结算）。

---

## 一、本地体验

```bash
cd hero-battle
npm install
node server.js
```

打开 `http://localhost:3000`：
- 点右下角 **🎮 主持人大屏** → 自动用当前地址生成学生扫码二维码（无需房间号）
- 手机/另一窗口打开同一地址 → 上传头像、输入昵称 → 加入 → 自动分组
- 大屏上人数 ≥ 2 后点 **⚔️ 开始战斗**

## 二、部署到国内公网 —— 微信云托管（推荐）

微信云托管（CloudBase Run）国内节点、原生支持 WebSocket、给已备案的公网分配域名，学生用微信扫码最顺。

### 步骤
1. **准备代码仓库**：把 `hero-battle` 整个文件夹推到你的 GitHub / GitLab / CODING 仓库（已含 `Dockerfile`、`.dockerignore`，请确认 `.gitignore` 排除 `node_modules`）。
2. **开通云托管**：微信扫码登录 [微信云托管](https://cloud.weixin.qq.com/cloudrun)，按提示开通 CloudBase 云开发环境（开发期/个人版可用 0 元额度）。
3. **新建服务**：控制台 → 服务 → **新建服务**，填写服务名称，开启 **「允许公网访问」**。
4. **部署方式选「代码仓库」**：关联你刚才的仓库，构建配置指定根目录 `hero-battle`、Dockerfile 路径 `/Dockerfile`。
5. **端口配置**：容器内监听 **3000** 端口（Dockerfile 已 `EXPOSE 3000`），创建/编辑服务时把 **「服务端口」设为 `3000`**。
6. **发布**：点部署，构建成功后平台会给出公网地址，形如 `https://xxx-xxx.run`（已备案分配域名）。

### 部署后拿二维码
- 主持人打开公网地址 → 点 **🎮 主持人大屏**，页面自动用该公网地址生成学生扫码二维码（WebSocket 会自动走 `wss://`，无需改代码）。
- 也可用 `qr.html` 把公网地址填进去生成/下载二维码图片。

> 提醒：若使用自有域名需要自行 ICP 备案；云托管分配的默认域名已备案，可直接用。

## 三、替代方案（若暂不实名国内平台）

### Render（国外，最快验证）
1. 把 `hero-battle` 推到 GitHub
2. Render → **New** → **Web Service**：Environment `Node`、Build `npm install`、Start `node server.js`、实例 `Free`
3. 得到 `https://hero-battle.onrender.com`，公网地址即学生扫码地址

## 四、配置项

| 变量 | 说明 | 默认 |
| --- | --- | --- |
| `PORT` | 服务端口 | 3000 |
| `TEAM_SIZE` | 每队人数上限，超出自动开新队 | 3 |

- **题库**：编辑 `questions.js` 增删改题目（题干、4 选项、正确下标、解析）。
- **自动分组**：优先放入人数最少的未满队伍；2 人及以上保证至少 2 队，各队人数尽量均衡。

---

## 五、项目结构

```
hero-battle/
├─ server.js        # WebSocket 服务端：加入、自动分组、答题判定、技能攻击、血量淘汰、排名
├─ questions.js     # 题库（可编辑）
├─ package.json     # 依赖（仅 ws）
├─ Dockerfile       # 微信云托管/云托管镜像部署
├─ render.yaml      # Render 一键部署配置（备选）
├─ qr.html          # 独立二维码生成/下载页
└─ public/
   └─ index.html    # 前端：学生扫码加入页 + 主持人大屏 + 答题/选目标/战斗/结算界面
```

> 本游戏为 WebSocket 实时多人对战，**必须运行在支持 WebSocket 的服务器**（Node.js 服务端），不能作纯静态页托管。扫码二维码内容为部署后的公网地址。
